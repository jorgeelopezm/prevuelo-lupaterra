## 9. Verification

Per the traceability rule, each item names the scenarios it covers. The library, runs, and history are Tier 2 (operational record-keeping); the seeded **emergency reference content is held to the Tier 1 no-fabrication bar** — the generic-content caveat and the no-aircraft-specific-claim assertions are mandatory and test-enforced. The home tile figure is Tier 3 chrome over a Tier 2 record.

- [x] 9.1 **Happy path — library.** Creating an aircraft seeds the nine checklists with their items in order and owned by the pilot; browsing renders both labeled groups; editing an item, renaming, reordering, adding, and deleting all persist. Covers `aircraft-checklists` → "Every aircraft has a checklist library…" (Seeding on aircraft creation), "Checklists are grouped as normal or emergency" (Grouped selector), "A pilot owns and edits their aircraft's checklists" (Creating a checklist, Editing an item, Reordering).
- [x] 9.2 **Happy path — runs.** Opening a normal checklist with an upcoming intent starts a run; toggling persists and updates the count; reopening resumes; confirming the last item completes it and states completion in text; a second open starts a new run and retains the completed one. Covers `checklist-runs` → "Running a normal checklist is scoped to a planned flight" (Starting a run, Resuming a run), "Confirming an item persists immediately" (Confirming, Un-confirming, Progress survives a reload), "A run completes when every recorded item is confirmed" (Completing a run, Starting again after completion).
- [x] 9.3 **Happy path — history.** Completed runs list per aircraft, most recent first, with checklist name, flight intent, and completion time; opening one shows its recorded items read-only. Covers `checklist-runs` → "Completed runs are kept and browsable per aircraft" (History listing, Opening a completed run).
- [x] 9.4 **Sad path — authorization.** Unauthenticated requests to every checklists route redirect to sign-in disclosing nothing; every cross-pilot aircraft, checklist, item, run, and history identifier answers 404. Covers `aircraft-checklists` → (Cross-pilot access is denied, Unauthenticated access) and `checklist-runs` → (Cross-pilot run access is denied, Unauthenticated access).
- [x] 9.5 **Sad path — invalid state.** Toggling or resetting a completed run is rejected and leaves it unchanged; starting, toggling, or resetting a run against an emergency checklist is rejected; designating an emergency checklist as pre-flight is rejected; an empty or whitespace-only name or item text is rejected with a localized field-named message. Covers `checklist-runs` → (Modifying a completed run, Resetting a completed run), `aircraft-checklists` → (Starting a run against an emergency checklist, Designation cannot go to an emergency checklist, Empty name is rejected).
- [x] 9.6 **Sad path — nothing to show.** A pilot with no aircraft, an aircraft with no checklists, a checklist with no items, a normal checklist with no upcoming flight intent, and an empty history each render their localized empty state and **no** name, item text, count, or progress. Covers `aircraft-checklists` → "Empty fleet state", `checklist-runs` → (No upcoming flight intent, Empty history).
- [x] 9.7 **Sad path — seeding.** A throwing seeder rolls back the aircraft insert. Covers `aircraft-checklists` → "Seeding failure does not create a half-created aircraft".
- [x] 9.8 **Eval — snapshot immutability (the change's central guarantee).** Editing, reordering, and deleting items after a run started leaves both the open run and every completed run showing exactly the recorded text and order; a run started after the edits records the new text. Covers `checklist-runs` → "A run records the items it was started from" (all four scenarios) and `aircraft-checklists` → "Deleting a checklist preserves completed runs" (both scenarios).
- [x] 9.9 **Eval — generic-content provenance (Tier 1 bar).** Every screen rendering a `source: 'template'` checklist contains the localized generic/not-POH caveat in text; no screen describes template content as the aircraft's own, approved, or certificated; the caveat disappears after the pilot's first edit; the emergency screen carries the ground-reference/no-offline statement. Covers `aircraft-checklists` → "Seeded content is labeled generic until the pilot makes it theirs" (all four scenarios) and "Emergency checklists are reference-only" (Connectivity caveat).
- [x] 9.10 **Eval — emergency is inert.** The rendered emergency screen contains no checkbox, toggle, counter, or progress markup, and no run row exists for an emergency checklist after visiting it. Covers `aircraft-checklists` → "Emergency checklists are reference-only" (No confirmation controls, Starting a run against an emergency checklist).
- [x] 9.11 **Eval — concurrency.** Two concurrent opens of the same checklist for the same flight intent yield exactly one open run. Covers `checklist-runs` → "No duplicate open runs". Live, `TEST_DATABASE_URL`-guarded.
- [x] 9.12 **Eval — shell contract.** Every checklists screen renders identically as a full page and as an htmx fragment of the same partial; every interactive control meets the 44px minimum; all visible chrome resolves from the catalogs in each of `es`/`en`/`pt`; path segments come from `chrome.ts`. Covers `aircraft-checklists` → "The checklists screen is fully localized and reachable on a phone" (all four scenarios).
- [x] 9.13 **Eval — no color-only meaning.** The emergency grouping, the completed state, and every unavailable state are each asserted present as text. Covers `aircraft-checklists` → (Emergency grouping is not color-only, Caveat is conveyed in text) and `checklist-runs` → "Completion is not color-only".
- [x] 9.14 **Eval — home tile.** Each null branch of `preflightProgressForIntent` renders its own localized unavailable message and no numeric value; the non-null branch renders the run's counts. Covers `home-dashboard` → "Status tiles show a sourced value or state why it is unavailable" (Checklists tile shows pre-flight progress, Checklists tile with no run started, Checklists tile with no flight to check against).
